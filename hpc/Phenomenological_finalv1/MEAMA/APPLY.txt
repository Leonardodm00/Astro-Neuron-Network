NOTES
=====
* The job scripts now read CONDA_ENV (default brian_final), forwarded by the
  launchers via qsub -v. To use a different environment for one run:
      CONDA_ENV=brian_test bash launch_bench.sh
  There is no hardcoded environment name left to drift.

* Every job now runs a guard immediately after `conda activate`: it imports
  urllib (the exact module missing from brian_env) and asserts that
  sys.executable lives under CONDA_PREFIX (catching the module-loaded system
  python winning on PATH). A bad environment now fails in the first seconds of
  a job with a clear message, not hours in.

* make_brian_final.sh installs: python 3.11, numpy, scipy, pandas, matplotlib,
  seaborn, scikit-learn, cython, gxx_linux-64 (a compiler inside the env, so
  cpp_standalone does not depend on whichever gcc a node exposes), then brian2
  via pip. That list came from the actual imports in HPC_main_sweep.py,
  HPC_single_run.py, ASD_fun_BD_cpp.py, aggregate_sweep.py, burst_metrics.py,
  burst_plots.py, seed_alloc.py and both smoke tests -- not from memory.

* VERSION REPRODUCIBILITY: the script records brian_env's package versions to
  brian_env_versions_<timestamp>.txt before building, and prints the key ones.
  `conda list` reads conda-meta/, so it works even though that interpreter is
  broken. If you need to reproduce the OLD campaigns numerically, pin brian2
  and numpy to those versions. For MEAMA (a new campaign family) current
  versions are fine -- but whichever you use becomes part of its provenance,
  so record it.

* Keep brian_env until brian_final passes env_check.py. Then remove it
  deliberately:  conda env remove -n brian_env

* Why brian_env broke is still unknown. Missing stdlib files on a shared home
  filesystem can indicate a quota or storage problem rather than a one-off. If
  it recurs in brian_final, check `quota -s` and raise it with the davinci
  admins -- a rebuilt environment will not survive a filesystem that is
  silently dropping files.
